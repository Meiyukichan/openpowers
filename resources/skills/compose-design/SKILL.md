# 整合设计文档

将用户提供的多个变更设计文档合并到项目的主设计文档中。

## 输入

- `主设计文档路径`：要更新或创建的项目主设计文档，位于当前项目根目录的 `project-design.md`
- `变更设计文档列表` <必填>：需要合并的变更设计文档列表

## 操作步骤

### 1. 检查主设计文档是否已存在

使用 bash 检查主设计文档是否已存在。

### 2. 文件不存在 — 创建

- 使用 read 工具读取用户提供的 `变更设计文档列表` 中的所有设计文档
- 识别核心架构章节：概述、组件、数据模型、接口、非功能性需求、流程图（以文字描述）等
- **智能合并：**
  - 去除重复信息
  - 合并相关章节（例如，同一 API 的两处描述应统一）
  - 当出现冲突时，保留更详细、更清晰的内容
- 使用 `#`、`##`、`###` 标题层级组织为结构良好的 Markdown 文档，并适当使用列表和表格
- 使用 write 工具写入 `主设计文档路径`

### 3. 文件已存在 — 使用 Edit 更新

- 使用 read 工具读取 `主设计文档路径` 的完整内容
- 使用 read 工具读取 `变更设计文档列表` 中的所有设计文档
- 分析新提供的设计文档，确定：
  - **新增章节**（例如，新的微服务、新的 API）
  - **已有章节的更新**（例如，数据字段变更、流程修改）
  - **冲突内容**（新信息与已有内容矛盾）— 优先采用较新的信息
- **使用 edit 工具更新文件**（推荐的精确编辑方式），遵循以下原则：
  - **插入新章节**：使用 edit 匹配附近的标题作为 `oldString`，在其后插入新章节，或追加到文档末尾
  - **替换整个章节**：匹配完整的标题及其内容作为 `oldString`，提供更新后的版本作为 `newString`
  - **在已有章节内添加细节**：找到插入点附近的唯一句子/段落，在其后扩展 [在同一功能模块内 — 不要在该模块之外的章节下添加内容]
  - 仅当更新涉及文档的大部分内容且 edit 不可行时，才使用 write 进行完整重写
- 编辑后，重新读取文件以确认结构和 Markdown 语法正确

### 4. 合并与一致性规则

- **不得**删除与本次更新无关的已有章节，除非用户明确要求
- 保持标题层级一致
- 保持格式风格一致（例如，如果文档使用 `## 组件`，新增组件应遵循相同风格）
- 当新设计引入全新的主要章节（例如，"认证模块"）时，将其作为顶层 `##` 标题添加在逻辑上合适的位置
- 每次操作后更新文档顶部的日期戳

### 5. 返回项目设计概要

你必须严格、准确地重新读取 `主设计文档路径` 的完整内容，然后从中提取一份 `项目参考指南文档`，该文档应准确包含以下内容：

```
## 项目关键功能
{这里填写该项目涉及到哪些关键功能模块}
## 参考指引
{这里必须准确填写：别的项目如何判断是否需要参考这个项目的指南}
```

将上述 `项目参考指南文档` 写入当前项目根目录的 `project-portrait.md` （注意这个文档不宜太大，不要超过50行）。

## 红线规则

- 不得读取 `主设计文档路径` 和 `变更设计文档列表` 以外的任何文档
- **`project-portrait.md`和`project-design.md`都必须使用中文**
