### 1. cc-switch: Model Fields in claudeProviderPresets.ts

**File**: `D:/project-code/llm/cc-switch/src/config/claudeProviderPresets.ts`

The four model fields are stored as environment variable key-value pairs inside `settingsConfig.env` of each preset:

| Field Name | Purpose | Example Value |
|---|---|---|
| `ANTHROPIC_MODEL` | Fallback default model (used when no role-specific model is configured) | `"deepseek-v4-pro"` |
| `ANTHROPIC_DEFAULT_SONNET_MODEL` | Model for the Sonnet role | `"deepseek-v4-pro"` |
| `ANTHROPIC_DEFAULT_OPUS_MODEL` | Model for the Opus role | `"deepseek-v4-pro"` |
| `ANTHROPIC_DEFAULT_HAIKU_MODEL` | Model for the Haiku role | `"deepseek-v4-flash"` |

**Usage patterns across presets:**

- Some presets use the same model value for all fields (single-model providers like Zhipu GLM):
  ```
  ANTHROPIC_MODEL: "glm-5"
  ANTHROPIC_DEFAULT_HAIKU_MODEL: "glm-5"
  ANTHROPIC_DEFAULT_SONNET_MODEL: "glm-5"
  ANTHROPIC_DEFAULT_OPUS_MODEL: "glm-5"
  ```

- Some presets differentiate between fast and powerful models (OpenRouter):
  ```
  ANTHROPIC_MODEL: "anthropic/claude-sonnet-4.6"
  ANTHROPIC_DEFAULT_HAIKU_MODEL: "anthropic/claude-haiku-4.5"
  ANTHROPIC_DEFAULT_SONNET_MODEL: "anthropic/claude-sonnet-4.6"
  ANTHROPIC_DEFAULT_OPUS_MODEL: "anthropic/claude-opus-4.7"
  ```

- Some presets omit model fields entirely (rely on default Claude models):
  ```
  // Claude Official presets: no ANTHROPIC_MODEL fields at all
  ```

**Annotation semantics:**
- `ANTHROPIC_MODEL`: The general default/fallback model. When Claude Code's request does not clearly target a Sonnet/Opus/Haiku role, this model is used. Usually can be left empty.
- `ANTHROPIC_DEFAULT_SONNET_MODEL`: Model name used when Claude Code requests a "Sonnet" role.
- `ANTHROPIC_DEFAULT_OPUS_MODEL`: Model name used when Claude Code requests an "Opus" role.
- `ANTHROPIC_DEFAULT_HAIKU_MODEL`: Model name used when Claude Code requests a "Haiku" role (usually the fastest/cheapest model).

These are standard Claude Code environment variables ([official documentation](https://docs.anthropic.com/en/docs/claude-code/config)).

Key implementation details:
- **parseModelsFromConfig()**: Parses settingsConfig JSON, extracts each model field from `env` object. Falls back to `ANTHROPIC_SMALL_FAST_MODEL` (legacy) or first available model.

- State management uses `useRef` for latest config and user editing detection to prevent external overwrites during user input.

### 3. openpowers: Current providers-store.ts Implementation

**File**: `D:/project-code/llm/openpowers/src/server/providers-store.ts`

**Zod Schemas:**

```ts
// Full provider object (server-generated fields)
const ProviderSchema = z.object({
  id: z.string(),
  name: z.string(),
  notes: z.string().optional(),
  websiteUrl: z.string().optional(),
  apiKey: z.string().optional(),
  baseUrl: z.string().optional(),
  icon: z.string().optional(),
  iconColor: z.string().optional(),
  createdAt: z.string(),
  updatedAt: z.string().optional(),
});

// Combined store file format
const StoreDataSchema = z.object({
  activeProviderId: z.string().nullable(),
  providers: z.array(ProviderSchema),
});

// Client create input (name + apiKey required, rest optional)
const ProviderInputSchema = z.object({
  name: z.string(),
  apiKey: z.string(),
  notes: z.string().optional(),
  websiteUrl: z.string().optional(),
  baseUrl: z.string().optional(),
  icon: z.string().optional(),
  iconColor: z.string().optional(),
});

// Client update input (all fields optional)
const ProviderUpdateSchema = z.object({
  name: z.string().optional(),
  apiKey: z.string().optional(),
  notes: z.string().optional(),
  websiteUrl: z.string().optional(),
  baseUrl: z.string().optional(),
  icon: z.string().optional(),
  iconColor: z.string().optional(),
});
```

**Data storage**: Single JSON file at `~/.openpowers/providers.json`, formatted with `indent=2`.

**CRUD Functions:**
- `ensureProvidersFile()`: Creates file with sample data if not exists
- `loadProviders()`: Reads and returns provider array from file
- `saveProviders(providers)`: Writes provider array, preserving activeProviderId
- `getProviderById(id)`: Finds and returns single provider
- `createProvider(input: ProviderInput)`: Generates UUID + createdAt, appends provider, saves
- `updateProvider(id, update: ProviderUpdate)`: Merge partial update, set updatedAt
- `deleteProvider(id)`: Removes from array, cascade-cleans active provider

**Active provider operations:**
- `getActiveProviderId()`: Returns string | null
- `setActiveProviderId(providerId)`: Validates existence, then writes
- `clearActiveProviderId()`: Sets to null

**Default data** contains two sample providers: Anthropic (id `000...001`) and OpenAI (id `000...002`), with no model fields.

### 4. openpowers: Current providers.ts Route Logic

**Route table:**

| Method | Path | Zod Validation | Response |
|---|---|---|---|
| GET | `/api/providers` | None | `200` JSON array |
| GET | `/api/providers/active` | None | `200` `{ activeProviderId }` |
| PUT | `/api/providers/active` | `SetActiveProviderSchema` (`{ providerId: string }`) | `200` / `404` |
| POST | `/api/providers` | `ProviderInputSchema` (name, apiKey required) | `201` provider / `400` |
| PUT | `/api/providers/:id` | `ProviderUpdateSchema` (all optional) | `200` provider / `400` / `404` |
| DELETE | `/api/providers/:id` | None | `204` / `404` |
| POST | `/api/providers/reset` | None | `200` `{ activeProviderId: null }` |

**Validation pattern**: Uses `safeParse` + `formatZodError` helper for consistent 400 error responses:
```ts
const parsed = ProviderInputSchema.safeParse(req.body);
if (!parsed.success) {
  res.status(400).json(formatZodError(parsed.error));
  return;
}
```

**Error handling pattern**: All update/set operations wrap in try/catch for 404 responses.
