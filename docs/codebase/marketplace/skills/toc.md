# Skills -- Furina Skill Definitions

> The 13 skill definitions (11 spec documents) that form the core intelligence of Furina. Each skill is a self-contained instruction set (SKILL.md + instructions/ + references/) orchestrating a specific phase of the software development lifecycle. The workflow stages are: Explore -> Propose -> Plan -> Review -> SDD -> Finalize, with cross-cutting skills (TDD, Cleancode, Codebase, Commit) providing specialized capabilities.

## Spec Documents

| Spec | Description | Source Files |
|------|-------------|--------------|
| [spec-skill-explore.md](./spec-skill-explore.md) | Multi-dimensional codebase exploration skill (Phase 1 of workflow). Orchestrates parallel subagent dispatch across 6 instruction types (codebase, repository, reference, specification, cleancode, memory) based on exploreType (for-design / for-coding). Supports language adaptation, RED LAW constraints, and output to structured exploration files. Routes to furina-codebase for document tree navigation and furina-cleancode for coding standards retrieval. | `marketplace/skills/furina-explore/SKILL.md`, `marketplace/skills/furina-explore/instructions/*.md`, `marketplace/skills/furina-explore/references/explore-dimensions.md` |
| [spec-skill-brainstorm.md](./spec-skill-brainstorm.md) | Thinking partner skill for the Propose phase (Phase 2 prerequisite). Defines a stance-based (not workflow-based) interaction model with 7 core stances: curious, open threads, align-first-ask-before-assuming (REA LAW), visual, adaptive, patient, grounded. Integrates with Furina change management to read exploration.md and existing artifacts. Managed by hooks system (brainstorm flag in settings.json, question capture to question.json). Supports 4 entry scenarios: vague ideas, concrete problems, mid-implementation blocks, and option comparison. | `marketplace/skills/furina-brainstorm/SKILL.md` |
| [spec-skill-propose.md](./spec-skill-propose.md) | Proposal artifact generation skill (Phase 2 core execution). Produces all change artifacts (proposal.md, design.md, specs/**/*.md) in a single pass through a serial pipeline driven by artifact status (ready/blocked/done). Integrates with CLI commands (furina change new/status/instruction) and lifecycle hooks (markBeginPropose/markEndPropose). Artifact creation strictly follows DAG: proposal -> design -> specs. Uses template-driven generation from resources/*.json files. | `marketplace/skills/furina-propose/SKILL.md`, `src/commands/change/new.ts`, `src/commands/change/status.ts`, `src/commands/change/instruction.ts`, `resources/*.json` |
| [spec-skill-plan.md](./spec-skill-plan.md) | Schema supplementation and implementation planning skill (Phase 3). Two-phase sequential execution: (1) Schema Instruction -- conditionally generates API (Swagger 2.0 YAML) and Database schema documents based on design.md content; (2) Plan Instruction -- decomposes specs into structured features in plan.json with dependency topology sorting, feature budget control (feature factor RED LAW), 30-500 LOC per feature, and 4-dimension self-review (spec coverage, dependency validity, file path consistency, acceptance criteria quality). | `marketplace/skills/furina-plan/SKILL.md`, `marketplace/skills/furina-plan/instructions/*.md`, `marketplace/skills/furina-plan/references/template-api.md`, `marketplace/skills/furina-plan/references/template-database.md` |
| [spec-skill-review.md](./spec-skill-review.md) | Artifact quality review skill (Phase 4). Dispatches a single review subagent that sequentially executes two review instructions: (1) Propose Review -- validates proposal.md/design.md/specs across 4 categories (proposal, design, specs, cross-document consistency) with calibration to avoid over-review; (2) Plan Review -- validates plan.json across 7 categories (JSON structure, feature granularity, dependency sorting, spec coverage, file path consistency, acceptance criteria quality, upstream consistency). Implements "review-as-fix" pattern: automatically creates fix tasks for Critical/Medium issues and resolves them. Controlled by experimental.review.furina config switch. | `marketplace/skills/furina-review/SKILL.md`, `marketplace/skills/furina-review/instructions/review-propose.md`, `marketplace/skills/furina-review/instructions/review-plan.md` |
| [spec-skill-sdd.md](./spec-skill-sdd.md) | Subagent-Driven Development skill (Phase 5). Main loop iterates through plan.json features, dispatching a fresh subagent per feature following a 9-step flow: mark in_progress -> reference explore (optional) -> implement -> handle questions -> spec compliance review -> quality review -> mark done. Each feature uses 4 subagent roles (reference explorer, implementer, spec reviewer, quality reviewer) with independent prompt templates and work guides. Supports implementer status handling (DONE/DONE_WITH_CONCERNS/NEEDS_CONTEXT/BLOCKED), lazy-loading strategy, and experimental config switches for optional steps. | `marketplace/skills/furina-sdd/SKILL.md`, `marketplace/skills/furina-sdd/instructions/complete-feature.md`, `marketplace/skills/furina-sdd/references/code-implementer.md`, `marketplace/skills/furina-sdd/references/code-implementer-prompt.md`, `marketplace/skills/furina-sdd/references/specs-reviewer.md`, `marketplace/skills/furina-sdd/references/specs-reviewer-prompt.md`, `marketplace/skills/furina-sdd/references/quality-reviewer.md`, `marketplace/skills/furina-sdd/references/quality-reviewer-prompt.md`, `marketplace/skills/furina-sdd/references/reference-explorer-prompt.md`, `marketplace/skills/furina-sdd/references/important-matters.md`, `marketplace/skills/furina-sdd/references/example-workflow.md` |
| [spec-skill-tdd.md](./spec-skill-tdd.md) | Test-Driven Development discipline skill. Defines the Iron Law ("no production code without a failing test first"), complete Red-Green-Refactor cycle with mandatory verification gates, good test principles (minimal/clear/shows intent), 11 common rationalization rebuttals, 13 red flag signals, and 5 testing anti-patterns (testing mock behavior, test methods in production code, mocking without understanding, incomplete mocks, after-the-fact testing). Mandatory skill loaded by SDD implementer subagent before writing any code. Pure guidance skill with no code logic -- depends only on test runner and human partner approval. | `marketplace/skills/furina-tdd/SKILL.md`, `marketplace/skills/furina-tdd/references/testing-anti-patterns.md` |
| [spec-skill-codebase.md](./spec-skill-codebase.md) | Codebase document tree infrastructure skill. Provides full lifecycle management of hierarchical documentation trees (toc.md indexes + spec documents) through 3 instructions: (1) explore -- 4-phase top-down navigation query from master index through module/submodule indexes to spec documents with source code tracing; (2) generate -- 5-phase tree construction from scratch using 10 SubAgent roles (partitioners, validators, generators, reviewers, checkers); (3) synchronize -- 5-phase incremental update for code changes with bottom-up index synchronization. Core concept: hierarchical docs solve LLM context window limitations for large codebases. | `marketplace/skills/furina-codebase/SKILL.md`, `marketplace/skills/furina-codebase/instructions/*.md`, `marketplace/skills/furina-codebase/references/guidance-*.md`, `marketplace/skills/furina-codebase/references/prompt-*.md`, `marketplace/skills/furina-codebase/references/template-*.md` |
| [spec-skill-cleancode.md](./spec-skill-cleancode.md) | Coding standards query skill. Two-layer architecture: SKILL.md (entry + routing) dispatches cleancode subagent via Agent tool. Currently supports TypeScript (clean-ts) with a 5-phase pipeline: context analysis -> standard reading -> guide generation -> relevance filtering (High/Medium/Low with 300-line limit) -> validation (6 mandatory checks). Python (clean-python) is an empty placeholder. References Google TypeScript Style Guide (9 chapters) plus project-specific core style rules. Called by furina-explore for coding-oriented exploration and by users directly before writing code. | `marketplace/skills/furina-cleancode/SKILL.md`, `marketplace/skills/furina-cleancode/instructions/clean-ts.md`, `marketplace/skills/furina-cleancode/references/cleancode-format.md`, `marketplace/skills/furina-cleancode/references/ts/toc.md`, `marketplace/skills/furina-cleancode/references/ts/naming.md`, `marketplace/skills/furina-cleancode/references/ts/source-file-basics.md`, `marketplace/skills/furina-cleancode/references/ts/source-file-structure.md`, `marketplace/skills/furina-cleancode/references/ts/type-system.md`, `marketplace/skills/furina-cleancode/references/ts/language-features.md`, `marketplace/skills/furina-cleancode/references/ts/comments-and-documentation.md`, `marketplace/skills/furina-cleancode/references/ts/policies.md`, `marketplace/skills/furina-cleancode/references/ts/toolchain-requirements.md`, `marketplace/skills/furina-cleancode/references/ts/typescript-core-style.md` |
| [spec-skill-finalize.md](./spec-skill-finalize.md) | Workflow finalization skill (Phase 6). Strict 4-step sequential pipeline: (1) Integration testing -- dispatches tester subagent with retry loops (max 3 rounds per feature), P0/P1/P2 priority verification, and implementer subagent for auto-fix; (2) Codebase sync -- reads staged files, groups by module path, serially calls furina-codebase synchronize; (3) Archive change -- executes furina change archive CLI command with artifact completion validation; (4) Git commit & push -- calls furina-commit skill. Implements RED LAW (progressive document reading). Integrates with change management via CLI commands (archive/status/list) and global memory synchronization. | `marketplace/skills/furina-finalize/SKILL.md`, `marketplace/skills/furina-finalize/instructions/*.md`, `marketplace/skills/furina-finalize/references/integration-testing.md`, `src/commands/change/archive.ts`, `src/commands/change/status.ts`, `src/commands/change/shared.ts`, `src/commands/change/list.ts` |
| [spec-skill-commit.md](./spec-skill-commit.md) | Git auto-commit and push skill. 5-step flow: environment check -> stage changes -> generate Conventional Commits message (with sensitive content scan) -> user-confirmed commit -> push to remote. Supports optional parameters: branch (target branch), type/scope (commit type override), push (enable/disable push), stage (all/specific files). Security policies: force push prohibition (double-confirmation required for --force-with-lease only), protected branch detection (main/master/release/*), sensitive content scanning, credential change blocking. Called by furina-finalize as its final step. | `marketplace/skills/furina-commit/SKILL.md` |
