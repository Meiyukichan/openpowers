在实验性工作流中归档已完成的变更。

**输入**：可选地指定变更名称。如未提供，检查是否能从对话上下文中推断出来。如果模糊或不明确，你必须提示用户从可用变更中选择。

**步骤**

1. **如果未提供变更名称，提示用户选择**

   运行 `openspec list --json` 获取可用变更列表。使用 **AskUserQuestion 工具**让用户选择。

   只显示活跃的变更（非已归档的）。
   如果可用，包含每个变更所使用的模式。

   **重要**：不要猜测或自动选择变更。始终让用户自己选择。

2. **检查产物完成状态**

   运行 `openspec status --change "<name>" --json` 检查产物完成情况。

   解析 JSON 以了解：
   - `schemaName`：正在使用的工作流
   - `artifacts`：产物列表及其状态（`done` 或其他）

   **如果有任何产物未标记为 `done`：**
   - 显示警告，列出未完成的产物
   - 使用 **AskUserQuestion 工具**确认用户是否要继续
   - 用户确认后继续

3. **检查任务完成状态**

   读取任务文件（通常是 `tasks.md`）检查未完成的任务。

   统计标记为 `- [ ]`（未完成）和 `- [x]`（已完成）的任务数量。

   **如果发现未完成的任务：**
   - 显示警告，列出未完成的任务数量
   - 使用 **AskUserQuestion 工具**确认用户是否要继续
   - 用户确认后继续

   **如果任务文件不存在：** 跳过任务相关警告，继续执行。

4. **执行归档**

   如果归档目录不存在，创建它：
   ```bash
   mkdir -p openspec/changes/archive
   ```

   使用当前日期生成目标名称：`YYYY-MM-DD-<change-name>`

   **检查目标是否已存在：**
   - 如果存在：报错失败，建议重命名已有归档或使用不同日期
   - 如果不存在：将变更目录移至归档

   ```bash
   mv openspec/changes/<name> openspec/changes/archive/YYYY-MM-DD-<name>
   ```

5. **显示摘要**

   显示归档完成摘要，包括：
   - 变更名称
   - 已使用的模式
   - 归档位置
   - 关于任何警告的说明（未完成的产物/任务）

**成功输出**

```
## 归档完成

**变更：** <change-name>
**模式：** <schema-name>
**归档至：** openspec/changes/archive/YYYY-MM-DD-<name>/

所有产物已完成。所有任务已完成。
```

**防护规则**
- 如果未提供变更名称，始终提示用户选择
- 使用产物图（`openspec status --json`）进行完成状态检查
- 不要因为警告而阻止归档——只通知和确认
- 移至归档时保留 `.openspec.yaml`（随目录一起移动）
- 展示清晰的摘要，说明发生了什么
