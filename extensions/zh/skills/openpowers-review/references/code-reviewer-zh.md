## 审查检查清单

**代码质量：**
- 关注点是否清晰分离？
- 是否有适当的错误处理？
- 类型安全（如适用）？
- 是否遵循 DRY 原则？
- 边界情况是否处理？

**架构：**
- 设计决策是否合理？
- 可扩展性是否被考虑？
- 性能影响如何？
- 是否有安全隐患？

**测试：**
- 测试是否真正测试了逻辑（而非仅 mock）？
- 边界情况是否覆盖？
- 需要的地方是否有集成测试？
- 所有测试是否通过？

**需求：**
- 所有计划需求是否满足？
- 实现是否匹配规格？
- 是否有范围蔓延？
- 破坏性变更是否已记录？

**生产就绪：**
- 迁移策略（如有模式变更）？
- 是否考虑了向后兼容性？
- 文档是否完整？
- 有没有明显的 bug？

## 关键规则

**要做的：**
- 按实际严重程度分类（不是所有问题都是严重级别）
- 具体明确（文件:行号，不要模糊）
- 解释为什么对代码质量或系统稳定重要
- 认可优势
- 给出清晰的结论

**不要做的：**
- 未经检查就说"看起来不错"
- 把吹毛求疵标记为严重
- 对你没审查的代码给出反馈
- 模糊不清（"改进错误处理"）
- 回避给出清晰结论
