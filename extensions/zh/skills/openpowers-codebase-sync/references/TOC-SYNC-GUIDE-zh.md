# 索引文件（toc.md）同步更新规范

> **重要提醒**：在更新任何 toc.md 文件之前，**必须重新读取本文件**，严格遵循以下所有规范。
>
> 本规范与 `openpowers-codebase-generator` 的 toc.md 生成规则完全一致，确保通过 `openpowers-codebase-sync` 更新的索引文件可被 `openpowers-codebase-explorer` 无缝查询。

---

## 一、核心原则

1. **索引文件是检索器（retriever）的导航入口**。描述必须足够详细以支持顺滑的导航路径：总纲 → 模块索引 → 子模块索引 → spec 文档。
2. **自底向上更新**。更新顺序必须是：子模块 toc.md → 模块 toc.md → 总纲 toc.md。先确认下级内容正确，再更新上级索引。
3. **索引文件 ≤ 500行**。它们是索引，不是详细文档。信息完整性优先于行数控制，但应尽量精简。
4. **每个条目必须有详细描述**，不能只写名称。描述应说明职责、覆盖范围、关键功能。
5. **所有链接使用相对路径**。

---

## 二、三级 toc.md 格式规范

### 2.1 总纲 toc.md

**路径**：`{文档树路径}/toc.md`

**格式**：

```markdown
# {项目名称} — 文档树

> 自动为 `{项目路径}` 生成的项目文档。

## 模块总览

### {模块A名称}

> {模块A详细简介：职责、覆盖的业务领域、关键功能}

- **子模块**
  - `{子模块1}` — {子模块1详细简介：职责说明、覆盖范围}（N个spec）
  - `{子模块2}` — {子模块2详细简介：职责说明、覆盖范围}（M个spec）
- **直接spec**
  - `spec-xxx.md` — {spec详细简介：覆盖的功能/接口说明}
  - `spec-yyy.md` — {spec详细简介：覆盖的功能/接口说明}
- **索引文件**：[模块A/toc.md](./module-a/toc.md)

### {模块B名称}

> {模块B详细简介：职责、覆盖的业务领域、关键功能}

- **子模块**
  - `{子模块3}` — {子模块3详细简介：职责说明、覆盖范围}（K个spec）
- **直接spec**
  - `spec-zzz.md` — {spec详细简介：覆盖的功能/接口说明}
- **索引文件**：[模块B/toc.md](./module-b/toc.md)
```

**关键要求**：
- 每个模块必须包含其子模块的详细简介和直接 spec 的详细简介
- 简介应说明职责和覆盖范围，而非仅名称
- 描述必须足够详细以支持检索器导航
- 总纲末尾**不得**添加任何统计信息章节（如"生成统计"、"文档统计"等）

### 2.2 模块 toc.md

**路径**：`{文档树路径}/{模块}/toc.md`

**格式**：

```markdown
# {模块可读名称}

> {模块详细简介：职责、覆盖的业务领域、关键功能}

## 模块关系图

```
┌─────────────────────────┐
│     {子模块A / 直接spec名称}      │
│     {描述或职责简述}              │
└───────────┬─────────────┘
            │
            ▼
┌─────────────────────────┐
│     {子模块B / 直接spec名称}      │
│     {描述或职责简述}              │
└─────────────────────────┘
```

## 子模块

| 子模块 | 描述 | Spec数 | 索引 |
|--------|------|--------|------|
| [submodule-1/](./submodule-1/) | {详细描述：职责说明、覆盖范围} | N个spec | [toc.md](./submodule-1/toc.md) |
| [submodule-2/](./submodule-2/) | {详细描述：职责说明、覆盖范围} | M个spec | [toc.md](./submodule-2/toc.md) |

## 直接 Spec 文档

| Spec | 描述 | 源文件 |
|------|------|--------|
| [spec-zzz.md](./spec-zzz.md) | {详细描述：覆盖的功能/接口说明} | `src/.../file.ts` |
```

**关键要求**：
- 模块关系图使用 ASCII 盒图（box-drawing characters）展示子模块之间的调用/依赖关系
- 子模块表格包含：名称链接、详细描述、spec 数量、索引文件链接
- 直接 spec 表格包含：名称链接、详细描述、源文件路径

### 2.3 子模块 toc.md

**路径**：`{文档树路径}/{模块}/{子模块}/toc.md`

**格式**：

```markdown
# {子模块可读名称}

> {子模块详细简介：职责说明、覆盖范围}

## Spec 关系图

```
┌─────────────────────────┐
│       {Spec A 名称}              │
│       {覆盖的功能简述}            │
└───────────┬─────────────┘
            │
            ▼
┌─────────────────────────┐
│       {Spec B 名称}              │
│       {覆盖的功能简述}            │
└─────────────────────────┘
```

## Spec 文档

| Spec | 描述 | 源文件 |
|------|------|--------|
| [spec-xxx.md](./spec-xxx.md) | {详细描述：覆盖的功能/接口说明} | `src/.../file.ts` |
| [spec-yyy.md](./spec-yyy.md) | {详细描述：覆盖的功能/接口说明} | `src/.../file2.ts` |
```

**关键要求**：
- Spec 关系图使用 ASCII 盒图展示 spec 之间的调用/依赖关系
- Spec 表格包含：名称链接、详细描述、源文件路径

## 三、更新规则

### 3.1 新增 spec 时的更新规则

当新增一个 spec 文档时：

1. **子模块 toc.md**：在 Spec 文档表格中添加一行，包含 spec 名称链接、详细描述、源文件路径。如有必要，更新 Spec 关系图。
2. **模块 toc.md**：如果 spec 是子模块下的，更新子模块的 spec 数量。如果是模块下的直接 spec，在直接 Spec 文档表格中添加一行。如有必要，更新模块关系图。
3. **总纲 toc.md**：在对应模块条目下添加/更新子模块或直接 spec 的详细简介。

### 3.2 更新 spec 时的更新规则

当更新一个已有 spec 的内容（如源文件路径变化、功能描述变化）：

1. **子模块 toc.md**：更新对应 spec 条目的描述和/或源文件路径。
2. **模块 toc.md**：如果描述有重大变化，同步更新。
3. **总纲 toc.md**：如果描述有重大变化，同步更新。

### 3.3 新增子模块时的更新规则

当新增一个子模块目录时：

1. 创建子模块目录和子模块 `toc.md`（初始骨架版本）。
2. **模块 toc.md**：在子模块表格中添加新行，包含子模块目录链接、详细描述、spec 数量、索引文件链接。更新模块关系图。
3. **总纲 toc.md**：在对应模块条目下的子模块列表中添加新条目。

### 3.4 删除 spec 时的更新规则

当一个 spec 文档因源代码被删除而需要移除时：

1. 删除对应的 spec 文件。
2. **子模块 toc.md**：从 Spec 文档表格中移除对应行。如有必要，更新 Spec 关系图。
3. **模块 toc.md**：如果 spec 是子模块下的，更新子模块的 spec 数量。如果是直接 spec，从直接 Spec 文档表格中移除对应行。如有必要，更新模块关系图。
4. **总纲 toc.md**：从对应模块条目下移除该 spec 的详细简介。

### 3.5 删除子模块时的更新规则

当删除操作导致某子模块下的 spec 少于 5 个时，应将剩余 spec 提升为模块下的直接 spec，删除子模块目录：

1. 将子模块下的剩余 spec 文件移动到模块目录下。
2. 删除子模块目录及其 `toc.md`。
3. **模块 toc.md**：从子模块表格中移除该子模块行。将提升的 spec 添加到直接 Spec 文档表格中。更新模块关系图。
4. **总纲 toc.md**：从对应模块条目下移除该子模块的详细简介，添加提升的 spec 简介。

### 3.6 描述更新规则

所有 toc.md 中的描述必须满足以下要求：

- **详细性**：不能只写名称，要说明职责、覆盖范围、关键功能
- **导航性**：用户给出一个查询描述（如"mcp的实现"），应能通过总纲 → 模块索引 → 子模块索引 → spec 文档的路径顺利定位
- **一致性**：同一模块/子模块/spec 在不同层级 toc.md 中的描述应保持一致

---

## 四、ASCII 关系图规范

所有关系图使用 Unicode 盒图字符（box-drawing characters），格式如下：

```
┌─────────────────────────┐
│       {名称}                    │
│       {简述}                    │
└───────────┬─────────────┘
            │
            ▼
┌─────────────────────────┐
│       {名称}                    │
│       {简述}                    │
└─────────────────────────┘
```

**规则**：
- 每个方框内包含名称和简述
- 箭头使用 `│` + `▼` 表示调用/依赖方向
- 方框宽度统一为 25 个字符（含边框）
- 关系图应反映模块/spec 之间的实际调用或依赖关系
