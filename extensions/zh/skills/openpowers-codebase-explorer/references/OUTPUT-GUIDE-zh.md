# 结果输出指南

> **重要提醒**：在输出最终结果之前，**必须先仔细阅读并理解本文件**，严格按照以下所有格式规范输出。每次生成结果前都要重新阅读本文件，确保完全遵循。

---

## 一、无结果处理

如果 `matched_specs` 为空（阶段一未命中任何模块/spec，或阶段三相关性验证过滤掉了所有条目），输出以下提示后结束：

```
========================================
查询："{查询描述}"
文档树：{文档树路径}
匹配结果：未找到与查询相关的 spec
========================================

可能原因：
1. 查询描述不够精确，尝试使用更具体的关键词
2. 文档树中尚未覆盖该功能模块
3. 该功能可能以其他名称存在于文档树中
```

---

## 二、有结果时的输出结构

按以下顺序和格式输出，每个部分之间用 `---` 分隔：

### 2.1 查询摘要

```
========================================
查询："{查询描述}"
文档树：{文档树路径}
匹配结果：共找到 N 个相关spec（已过滤掉 M 个不相关条目）
========================================
```

### 2.2 导航路径

根据 `matched_specs` 中每个条目的 `match_source` 和 `spec_path`，还原从总纲到 spec 的完整导航路径：

```
路径 {序号}：
  （总纲直接命中）总纲 → spec-{功能名}.md
  （模块直接spec）总纲 → {模块名} → spec-{功能名}.md
  （子模块spec）总纲 → {模块名} → {子模块名} → spec-{功能名}.md
  匹配原因：{match_reason}
```

### 2.3 Spec 摘要

对每个匹配的 spec，输出其核心内容摘要（从 spec 文档中提取）：

```
---
## Spec: {spec标题}

源文件：
- {源文件路径} : {行号范围}

概述：{spec的概述部分，对于spec里面涉及到要查询的功能的部分要详细一点}

关键功能/接口：
- {接口1签名}：{一句话说明}
- {接口2签名}：{一句话说明}

核心数据结构：
- {类型名}：{一句话说明}
```

### 2.4 源码片段

对每个匹配的 spec，输出其完整的源码实现，包括 spec 直接关联的源码和上下游追溯到的源码：

#### 源码长度规则

- 本段摘录 ≤ 100 行时，必须完整输出，不得精简
- 本段摘录 > 100 行时，可对不重要的代码进行适当省略，但必须保留足够丰富的代码细节，尤其是核心代码逻辑，不得出现注释占主体而实际代码寥寥无几的情况

#### 【强制】省略标注要求（针对源码片段）

省略代码时必须同时满足以下三点，缺一不可：

1. 在省略处写注释说明省略了第几行到第几行、以及原本代码的逻辑和功能
2. 注释行下方另起一行单独写 `...`，不得将省略号写在注释里
3. 原始源码中的无关注释应一并省略（删除），只保留模型生成的省略标注

**示例**：
```typescript
export async function registerTool(def: ToolDef): Promise<void> {
  if (!def.name || typeof def.name !== 'string') {
    throw new Error('tool name must be a non-empty string');
  }
// （省略第 15-30 行：schema 校验和默认值填充逻辑）
...
  registry.set(def.name, def);
}
```

#### 【强制】上下游调用方（针对源码片段）

上下游调用方的源码片段属于功能性参考，应当尽量保留有参考价值的核心片段，不得省略。

#### 源码片段格式模板

````
---
## 源码：{spec标题}

### 直接源码

来源：{文件路径}:{起始行}-{结束行}（本段摘录共 {结束行-起始行+1} 行）

```{语言}
// spec 直接关联的源文件代码
// （省略第 25-80 行：参数校验和默认值处理逻辑）
...
```

说明：{这段代码的作用，与 spec 中哪个功能/接口对应}

### 上游调用方

来源：{调用方文件路径}:{起始行}-{结束行}（本段摘录共 {结束行-起始行+1} 行）

```{语言}
// 调用了上述代码的上游代码片段
```

说明：{上游如何调用本功能，在什么场景下触发}

### 下游依赖

来源：{被依赖文件路径}:{起始行}-{结束行}（本段摘录共 {结束行-起始行+1} 行）

```{语言}
// 本功能所依赖的下游代码片段
```

说明：{本功能依赖了哪些底层能力，关键调用关系}
````

---

## 三、【强制】源码必须输出

**每个匹配的 spec 必须同时输出其关联的源码片段**，不能只输出 spec 文档摘要。**必须识别并优先选取该功能最核心的承载文件**，不得随意选取边支文件或罗列所有相关文件，应判断哪个文件是核心逻辑的主要实现。即使需要大量省略，也必须保留核心代码片段，**绝不能空缺**。

源码片段包含三个部分，每个都必须有：
- **直接源码**：spec 直接关联的源文件代码
- **上游调用方**：调用了这些代码的上游代码片段
- **下游依赖**：本功能所依赖的下游代码片段

---

## 四、【强制】输出前自检清单

在输出最终结果之前，逐项检查：

1. [ ] 无结果时输出了规范提示，无遗漏
2. [ ] 查询摘要的 `========================================` 分隔线完整
3. [ ] 每个 spec 都有对应的 `---` 分隔
4. [ ] 每个 spec 都有源码片段三部分（直接源码、上游调用方、下游依赖），**不得空缺**
5. [ ] 源码省略时满足三点要求：省略标注行、`...` 独立成行、删除无关注释
6. [ ] 省略示例中的 `...` 单独一行，不在注释里
7. [ ] 上下游调用方保留核心片段，未被省略
8. [ ] Spec 摘要中的概述部分对查询相关功能描述详细
